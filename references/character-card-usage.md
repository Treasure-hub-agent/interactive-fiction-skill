# 通用角色卡库·存储结构与读取模式

> 根路径：`{存储根}/通用角色卡/characters/`
> 来源：蒸馏卡（7文件完整）或自制卡（1文件profile起步）

## 目录结构（按作品分文件夹）

```
{存储根}/通用角色卡/characters/
├── _roster.json              ← 索引（每项含 work + path 字段）
├── 《示例作品A》/
│   ├── 示例角色A/
│   │   ├── profile.md
│   │   ├── personality.md
│   │   ├── interaction.md
│   │   ├── memory.md
│   │   ├── relations.md
│   │   ├── SKILL.md
│   │   └── manifest.json
│   └── 示例角色B/  ...
├── 《示例作品》/
│   └── 示例角色C/  ...
└── 自创/
    ├── 示例角色D/  ...
    └── 示例角色E/  ...
```

- 作品文件夹格式：`《作品名》`。自创角色统一集中在 `自创/`（不加书名号）。
- `_roster.json` 每项增加 `work` 和 `path` 字段（见下）。

### _roster.json 格式

```json
{
  "示例角色A": {
    "name": "示例角色A",
    "work": "示例作品A",
    "slug": "示例角色A",
    "type": "fictional",
    "path": "《示例作品A》/示例角色A/"
  },
  "示例角色D": {
    "name": "示例角色D",
    "work": "自创",
    "slug": "示例角色D",
    "type": "original",
    "path": "自创/示例角色D/"
  }
}
```

| 字段 | 说明 |
|------|------|
| `work` | 归属作品名（蒸馏=作品名，自创="自创"）。用于分组展示。 |
| `source` | `distill`（蒸馏）或 `custom`（自创）。 |
| `path` | 实际存储路径，相对于 `characters/`。 |

### 自动归入规则（落盘时触发）

| 来源 | work 判定 | 落盘路径 |
|------|-----------|----------|
| 蒸馏（title_distillation / txt distillation） | 蒸馏时确定的作品名 | `characters/《作品名》/{角色名}/` |
| 深度创建·简化模式 | `自创` | `characters/自创/{角色名}/` |
| 深度创建·九维（用户指定了作品） | 用户指定的作品名 | `characters/《作品名》/{角色名}/` |
| 深度创建·九维（未指定作品） | `自创` | `characters/自创/{角色名}/` |

- 作品文件夹不存在 → 自动创建。
- 落盘同时更新 `_roster.json`。

## 列表展示格式

```text
🃏 通用角色卡库 — 共 N 张
  1. 示例角色A · 《示例作品A》
  2. 示例角色B · 《示例作品A》
  3. 示例角色C · 《示例作品B》
  4. 示例角色D · 自创
```

- 默认按作品分组，同作品连续展示，作品之间空行分隔。
- 自创角色统一在最后分组。

## 指令：「查看XXX作品的角色卡」

- 触发：`查看{作品名}的角色卡` / `查看《作品名》角色卡` / `{作品名}有哪些卡`
- 扫描 `characters/《作品名》/` 目录。
- **文件夹存在** → 列出该作品下全部角色卡。
- **文件夹不存在** → 提示：
  ```
  未找到《XXX》的角色卡。是否联网检索蒸馏？
  A. 是 — 对《XXX》执行作品名检索蒸馏（见 extended/title_distillation.md）
  B. 否
  ```
- 「查看自创的角色卡」→ 列出 `characters/自创/` 下所有卡。

## 7文件速查

| 文件 | 场景卡时 | 主线剧情时 | 说明 |
|:----|:--------:|:----------:|------|
| `profile.md` | ✅ **必读** | ✅ **必读** | 外貌、身份、基本信息 |
| `personality.md` | ✅ **必读** | ✅ **必读** | 性格关键词、内在矛盾、行为模式 |
| `interaction.md` | ✅ **必读** | ✅ **必读** | 声线基因、说话方式、口头禅 |
| `memory.md` | ⏸️ 按需 | ⏸️ 按需 | 关键背景故事，涉及前情时才读 |
| `relations.md` | ⏸️ 按需 | ⏸️ 按需 | 人际关系，场景涉及其他角色时才读 |
| `SKILL.md` | ⏸️ 按需 | ⏸️ 按需 | 角色技能/能力体系，战斗/能力场景才读 |
| `manifest.json` | ❌ 不读 | ❌ 不读 | 元数据/版本号，仅供升级校验 |

## 读取原则

- **场景卡 / 独立单元场景**：读 profile + personality + interaction 三件套即可覆盖角色表现所需。用户补充场景设定后，将三件套完整内容 + 场景设定打包给子Agent生成正文。
- **主线剧情蒸馏**：读全部 6 个 md 文件（不含 manifest.json）做完整角色蒸馏。
- **角色卡不自作主张修改**：读取后做角色设定参考，不修改原卡文件、不影响原卡数据。

## 存量兼容

- 旧扁平结构（`characters/{slug}/` 直接在根下）的卡**不做强制迁移**。
- `_roster.json` 旧条目缺 `work` 字段时，AI 扫描时降级处理：`characters/{slug}/` 视为旧卡，`work` 显示「未分类」。
- 用户重新蒸馏或重新创建时自动归入新结构。
