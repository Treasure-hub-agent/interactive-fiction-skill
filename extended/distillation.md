# 角色蒸馏系统（P2 按需加载）

> 本章为互动小说创作的**前置环节**：当用户基于游戏/小说原作开启创作但尚未拥有可扮演角色卡时，AI 应优先执行本章流程，从原作材料中蒸馏角色设定与世界观信息，再进入后续章节的路线选择与叙事创作。若用户已有角色卡或直接开始原创创作，可跳过本章。

**数据源**：本章支持两种蒸馏数据源——① 用户上传的原作 txt 全文（见下文各 Phase）；② 用户给出的作品名，由 AI 联网检索后蒸馏（见 `extended/title_distillation.md`）。两种数据源下游的蒸馏 schema（世界观/角色五维/剧情大纲）完全一致。

---

### 0.0 外貌描写规则（蒸馏专用覆盖）

角色蒸馏期间，`references/appearance.md` 的三区分级（🟢可细写/🟡适度提及/🔴仅情感场景）**不适用**。蒸馏执行体在提取和描写角色外貌（profile 维度）时：

- **全面还原**：搜索素材或设定文本中涉及的角色外貌特征——脸型、五官、发型、身形、肩颈、腰肢、胸部、臀部、腿线、体香、肤质、着装材质与剪裁等——一律如实、详尽描写，不做任何分区回避或省略
- **禁用术语**：产出中禁止出现"适度提及""一笔带过""不展开""🟡""🟢""🔴"等分区自限词汇——这些术语对蒸馏场景无意义

### 1.1 背景理念

「夺舍」指接收原设后快速变强的创作思路。对应到创作场景：**接收设定 → 分维度提取 → 证据分级 → 冲突记录 → 输出可扮演的角色 Skill**。

核心原则：不编造官方设定中不存在的剧情或关系，不混淆不同版本的角色设定，不将玩家二创当作官方设定，不跳过测试直接输出。

### 1.2 操作流程总览

| 阶段 | 名称 | 要点 |
|------|------|------|
| Phase 1 | 接收角色设定 | 选择游戏/Wiki来源获取材料；材料缺失项降级处理 |
| Phase 2 | 分维度提取 | 五维：profile/personality/interaction/memory/relations；每条标注证据级别（verbatim/artifact/impression） |
| Phase 3 | 冲突检查 | 检查不同来源设定矛盾，写入 conflicts.md |
| Phase 4 | 生成 Skill 文件 | 输出 output/characters/\<slug\>/ 下 SKILL.md + 各维度 md 文件 |
| Phase 5 | 告知用户 | 汇报文件路径、证据覆盖度、设定冲突 |
| Phase 6 | 扮演测试 | 8 场景覆盖（初次见面/日常闲聊/核心话题/正面情绪/负面情绪/压力/关系/OOC），通过率≥70%；或选 D 对话试演 3-5 轮（按五维汇报吻合度，可并入 memory.md） |
| Phase 7 | 质量评分 | 完整度30%+证据率40%+冲突数10%+测试通过率20% |

#### 断点保存与恢复

蒸馏流程每个 Phase 完成后，AI 自动将当前阶段的中间数据写入 `output/characters/<slug>/_checkpoint.json`（含已完成的 Phase 编号和各维度已提取数据）。若会话中断后重新进入蒸馏：

1. 检测 `_checkpoint.json` 是否存在 → 弹出「检测到未完成的蒸馏流程（已完成 Phase N/7），是否继续？」
2. A. 继续 → 从断点恢复，跳过已完成的 Phase
3. B. 重新开始 → 清除断点，从 Phase 1 开始
4. C. 跳过蒸馏 → 放弃蒸馏，直接进入叙事（角色设定将依赖模型知识 + 用户口头描述）

`_checkpoint.json` 在 Phase 7 评分完成后自动清除。

### 极速蒸馏（可选快捷入口）

进入 Phase 1 前，AI 先询问是否启用极速蒸馏，将原本 7+ 轮交互压缩为 1 次确认：

> 「是否极速蒸馏？
> A. 极速蒸馏 —— AI 后台一次性跑完 Phase 1-7（模型知识生成角色卡 + 五维提取 + 冲突检查 + 质量评分），仅输出最终角色卡与质量分，你确认即生效
> B. 完整蒸馏 —— 按原 Phase 1-7 逐阶段交互（含扮演测试）」

- 选 A：AI 执行完所有 Phase 后，仅输出最终角色卡摘要 + 质量评分，并请求一次确认（1 轮确认 vs 完整流程 7+ 轮）；确认后跳过扮演测试逐场景交互，质量分仍出具，用户可要求「完整蒸馏」回退补测
- 选 B：走原 Phase 1-7 流程（无变化）
- 极速蒸馏产物与完整流程一致：同样写入 `output/characters/<slug>/` 下的完整 Skill 文件，`_checkpoint.json` 在 Phase 7 后清除

### Phase 1：接收角色设定

询问用户作品类型（热门二游/动漫/其他）。优先从对应的 Wiki / 角色数据站获取材料。材料完整性校验：语音台词/人物关系/角色故事/官方评述缺失时对应维度降级。

### 冷门配角轻量卡路径（信息量低时）

当素材仅含少量信息（如配角只有几句台词 / 背景资料不足）时，Phase 2 **不硬凑五维**：

- 降级为**轻量卡**：仅输出 `身份 / 性格关键词（3-5 个）/ 关系定位` 三字段 + `manifest.json` 标注 `lite: true` + 低充足度维度标注 `[待补]`
- 轻量卡同样落盘（`output/characters/<slug>/`），结构兼容完整卡
- 用户可随时通过「补全角色卡」走深度创建（`deep_character_creation.md`）或补传材料重新蒸馏，渐进升级为完整五维
- **判定阈值**：五维中 ≥3 维无法提取到有效内容 → 走轻量卡

### Phase 2：分维度提取

按 profile/personality/interaction/memory/relations 五维依次提取。每条标注证据级别（verbatim=角色原话 / artifact=官方设定文本 / impression=其他角色评价）。profile 维度含**存在形态**（人类 / 非人 / 化身 / 组织 / 多身份），覆盖神明、人造人、兽耳、福瑞、历史人物等角色。`memory` 与 `relations` 交叉事件仅在 memory 中详写，relations 中仅写关系影响。

### 信息充足度评估（强制）

Phase 2 提取完成后，对五个维度逐一标注**充足度**：

| 等级 | 判定 | 处理 |
|------|------|------|
| 高 | 多源 / 原文直接支撑 | 正常落卡 |
| 中 | 单源或模型推断 | 标注来源，正文中自然印证 |
| 低 | 几乎无资料 | 对应维度文件标注 `[待补]`，Phase 5 汇报时列出，用户可后续「补全角色卡」渐进补全 |

低充足度维度**禁止编造**：宁可留空标注 `[待补]`，不得凭空补全官方未提供的信息。

### Phase 3：冲突检查

检查不同来源设定矛盾（版本差异、官方与实装差异、多来源事件描述不一致）。矛盾项写入 `conflicts.md`，格式：`| 冲突项 | 来源A | 来源B | 证据A | 证据B | 处理建议 |`

### Phase 4：生成 Skill 文件

输出 `output/characters/<slug>/` 目录，含：SKILL.md（入口，<100行）、profile.md、personality.md、interaction.md、memory.md、relations.md、conflicts.md（如有）、manifest.json。（蒸馏中间产物，最终落盘后迁移至 {存储根}/ 正式路径）

### Phase 5：告知用户

生成完成后，AI 先输出**轻量角色卡**（即时展示，省 token）：

> `{角色名} · {路线} · 一句话定位`
> 质量分：{X.X}（{评级}）｜ 证据覆盖：verbatim+artifact {Y}% ｜ 冲突：{N} 条
> 📂 回复「展开」查看完整 7 文件角色树（profile/personality/interaction/memory/relations/conflicts/manifest）

- 用户回复「展开」/「弹出{角色名}角色卡」→ 输出完整文件树与逐维度细节（按需加载，不占每轮前缀）
- 不回复则保持轻量卡，进入后续步骤（扮演测试 / 质量评分）

> 轻量卡仅为**展示层精简**；完整 Skill 文件仍按 Phase 4 全部落盘（`output/characters/<slug>/`），保证 canon 保真与可回溯，不受展示精简影响。

### Phase 6：扮演测试

进入测试前，AI 先输出模式选择：

> 🔬 扮演测试 · 8 场景验证角色一致性
>
> A. 逐场景交互 — 每轮展示一个紧凑测试卡片，你逐条确认（推荐）
> B. 批量汇报 — AI 后台一次性跑完 8 场景，汇总展示判定结果与修正建议
> C. 跳过测试，由 AI 判定吻合度 — 不进场景交互，基于角色卡内容直接评出各维度吻合概率
> D. 对话试演 — 以角色卡身份与用户**自由对话 3-5 轮**（不预设场景，用户自由发挥），结束后 AI 按五维汇报吻合度与修正建议；试演对话可一键并入角色卡 `memory.md`

- 选 A → 逐场景展示测试卡片（见下方模板）。8 轮逐场景走完。
- 选 B → AI 静默跑完所有场景，最后输出汇总卡：`场景 N/8 · 名称 · ✅/⚠️ · 偏离项 · 修正建议`，一次确认。
- 选 C → 不生成场景对话，AI 基于五维角色卡逐维度评估吻合度，输出概率表 + 风险项，计入 Phase 7 质量评分。用户可事后要求「补测场景X」针对单场景验证。
- 选 D → 进入对话试演（见下方流程）。试演不参与 8 场景通过率统计，其五维吻合度由 AI 判定后计入 Phase 7 质量评分（测试通过率权重按判定折算）。

**对话试演流程（选 D 时使用）：**

```
🎭 对话试演 — 以角色卡身份自由对话 3-5 轮

> 现在我就是{角色名}。请随意对我说话、提问或抛出情境，
> 我会以角色卡的人设、声线与性格回应（不输出任何判定）。
> 对话满 3-5 轮后发送「结束试演」，我会给出五维吻合度报告。
```

1. AI 全程以角色卡身份回应，**不展示判定/标签**，保持沉浸式对话
2. 用户自由发挥 3-5 轮（台词 / 提问 / 情境均可）；用户可随时发「结束试演」提前收尾
3. 结束后 AI 输出试演报告：

```
🎭 试演报告 · {角色名}
  · profile（外貌/身份）：✅ 符合 / ⚠️ {偏差说明}
  · personality（性格）：  ✅ / ⚠️ ...
  · interaction（声线/口癖）： ✅ / ⚠️ ...
  · memory（背景/经历）： ✅ / ⚠️ ...
  · relations（关系/立场）： ✅ / ⚠️ ...
  · 修正建议：{逐条列出}
A. 并入 memory.md（追加「试演对话样本」区块，供后续叙事参考）
B. 不并入
```

4. 选 A → 将本次试演对话（角色台词部分）追加到角色卡 `memory.md` 末尾「试演对话样本」区块（标注日期与结论摘要）；选 B → 仅保留报告，不落盘

8 场景覆盖：初次见面/日常闲聊/核心话题/正面情绪触发/负面情绪触发/压力场景/关系测试/OOC检测。通过率 ≥70%（6/8）视为通过，否则提示补充薄弱维度。

**逐场景测试卡片模板（选 A 时使用）：**

```
🔬 扮演测试 场景 {N}/8 · {场景名称}

> 触发句：「{AI 生成一句触发当前场景的角色台词}」

角色反应：「{AI 基于角色卡生成 1-2 句角色回应}」

判定：✅ 符合{维度} / ⚠️ {维度}偏差 — {具体说明}。{修正建议}

A. 继续下一场景  B. 展开完整对话  C. 跳过剩余，AI批量判定
```


### Phase 7：质量评分

| 维度 | 权重 |
|------|------|
| 完整度（五维均有内容） | 30% |
| 证据率（verbatim+artifact占比） | 40% |
| 冲突数（0冲突=满分） | 10% |
| 测试通过率 | 20% |

评级：≥0.85优秀 / 0.70-0.84良好 / 0.60-0.69及格 / <0.60不合格。

评分完成后更新 `manifest.json` 添加 `quality_score` 字段，生成质量报告 Markdown 文件。

> Phase 7 结束后，蒸馏产物的角色卡自动落盘：
> - 若在创建小说流程中 → `{存储根}/{小说名}/characters/<slug>/`
> - 若在角色卡管理中独立蒸馏 → `{存储根}/通用角色卡/characters/<作品名>/<slug>/`
> `output/` 为蒸馏中间产物的暂存区（相对当前工作目录），最终落盘至 `{存储根}/` 正式路径；临时文件可保留至下次蒸馏覆盖。

### 1.3 用户纠正流程

用户对提取结果有异议时：

1. 询问纠正来源（官方 Wiki / 游戏内文本 / 角色台词 / 我的理解）
2. 验证来源（如提供链接或截图）
3. 根据证据级别决定修改策略：`user_impression` 不覆盖官方设定，追加到文件末尾

### 1.4 版本更新流程

检测到游戏版本更新时：

- 对比 `manifest.json` 中的 `source_version` 与当前版本
- 询问用户选择更新策略：完整更新（重新蒸馏所有维度）或增量更新（仅更新变化部分）

### 1.5 自检清单

- [ ] `name` 与目录名一致且符合命名规则
- [ ] 每个维度文件都有证据标注
- [ ] `verbatim` 和 `artifact` 占比达标
- [ ] `impression` 隔离到专属区
- [ ] `conflicts.md` 反映真实矛盾（不虚构）
- [ ] `SKILL.md` 正文 < 100 行
- [ ] 扮演测试执行并通过（≥70%）
- [ ] 质量评分 ≥ 0.60
- [ ] `manifest.json` 包含完整元数据

## 数据获取策略（开局/角色卡生成必守）

> 本节从 SKILL.md P0 迁入。蒸馏流程及角色卡生成时遵循此策略。

> **铁律**：模型知识优先 → 询问用户 → 用户确认后才联网搜索。**禁止自行发起联网搜索。**

| 优先 | 场景 | 行为 |
|:--:|------|------|
| 1 | 热门二游/动漫 | 直接凭模型知识生成角色卡和世界观 |
| 2 | 冷门作品 / 知识不足 | **先问用户**「是否需要查资料」，不自行搜索 |
| 3 | 用户明确要求 / 给了 wiki 链接 | 按指令搜索，但止盈：身份+性格+能力到手即停，外貌正文现场写 |

> **原理**：热门作品的角色设定在训练数据中已充分覆盖。游戏 WIKI 通常只有数值表格，没有叙事向的外貌/背景描写，爬了也是白爬。详见 `references/original-role-data.md`。

> 若用户希望以作品名为输入做联网检索蒸馏（而非直接凭模型知识生成角色卡），流程见 `extended/title_distillation.md`（同样遵循本铁律：需用户确认才发起检索）。
