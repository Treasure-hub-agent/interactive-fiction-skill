# 深度自定义角色创建（P2 按需加载）

> 本章为角色卡的增强创建入口。用户在剧情中或开局时可通过「自定义角色」指令触发，进入 AI 引导式九维角色创建流程。核心特性：用户只需填写想填的维度，留空处由 AI 根据已有信息智能补全，不设必填项。

---

## 触发指令

| 指令 | 行为 |
|------|------|
| `自定义角色` / `深度创建角色` / `创建角色` | 进入九维引导流程 |
| `自定义角色 {角色名}` | 指定角色名后直接进入，跳过命名环节 |
| `补全角色卡` | 对当前已弹出角色卡中留空字段做 AI 批量补全 |

**边界**：由 SKILL.md §非剧情阶段指令边界 和 §按需加载指引 统一管控。爽文/主线/场景卡中可触发；沉浸模式中触发自动退出；其余阶段按 SKILL.md 规则拦截。

---

## 创建流程

### 概览：四轮问答

| 轮次 | 维度 | 理由 |
|------|------|------|
| 第 1 轮 | ① 身份与外貌 + ② 角色定位 | 先确立"是谁"，为后续推断打地基 |
| 第 2 轮 | ③ 性格核心 + ④ 内心动力 | 基于身份推断性格与驱动 |
| 第 3 轮 | ⑤ 声线基因 + ⑥ 关键背景 | 基于性格导出声线特征与经历 |
| 第 4 轮 | ⑦ 成长弧线 + ⑧ 人际关系 + ⑨ 能力技能 | 基于前六维推断动态发展 |

每轮 AI 展示当前维度 + 根据已填信息生成的**AI 推荐值**（用户可一键确认或修改）。

## 🔴 AI 自动补全规则（核心）

> AI 补全的目标是**降低用户填卡负担**——用户只需填自己最在意的维度，其余由 AI 根据已填内容推断生成。

### 补全触发条件

| 场景 | 行为 |
|------|------|
| 用户完成四轮问答后 | AI 对全部留空字段执行批量补全，展示完整卡片供确认 |
| 用户在任意轮选择「跳过本轮」 | 本轮维度全部留空，进入下一轮，最后统一补全 |
| 用户只说了一个大致方向（如「一个冷艳型剑士」） | 在开始四轮问答前，AI 先根据该方向生成全部九维的初稿卡片，然后逐轮让用户确认或修改 |
| 用户使用「补全角色卡」指令 | 对当前已弹出角色卡的留空字段做补全，仅针对角色卡格式存在的字段 |

### 补全推理链（优先级顺序）

AI 在补全每个留空维度时，按以下推理链依次查找可用的已知信息：

```
已填的 身份+外貌+定位
  → 推断 性格核心 + 出身背景（社会阶层→性格倾向）
    → 推断 内心动力（性格→欲望/恐惧）
      → 推断 声线基因（性格+身份→声线特征）
        → 推断 关键背景（性格+出身→经历事件）
          → 推断 成长弧线（性格+背景→变化方向）
            → 推断 人际关系（身份+定位→关联角色）
              → 推断 能力技能（身份+定位→战斗/职业能力）
```

**交叉推断示例**：
- 已填"孤儿出身的杀手" → AI 补全性格为"冷静克制 / 不信任他人" → 补全内心动力为"想要自由 / 怕被抛弃" → 补全声线为"短句/话少/从不自称"
- 已填"性格暴躁 + 元素系能力者" → AI 补全能力巅峰为"近战神挡杀神，但能量耗尽后极其脆弱" → 补全成长弧线为"从被力量驱使→学会驾驭力量"

### 补全约束

| 规则 | 说明 |
|------|------|
| **不编造既有设定** | 若世界观/剧情已有明确规则，补全必须遵守 |
| **不覆盖用户已填内容** | 补全仅作用于留空字段，用户已填的一字不改 |
| **不在补全中引入未登场角色** | 人际关系的补全仅使用已出场/NPC 名字，不给名字就留空 |
| **成长弧线不预设结局** | 若故事未完成，终点状态用「？（待故事展开）」标注 |
| **补全后标注来源** | 每条 AI 补全的字段末尾加 `[AI推断]` 标记，用户确认后移除 |

### 补全确认流程

1. AI 补全所有留空字段后，输出完整角色卡
2. 底部提示：
   ```
   > 以下字段为 AI 根据已有信息推断补全：
   > · {字段1}、{字段2}、...
   > 确认输入「确认」保存 | 修改输入「改{字段} 新内容」| 推翻输入「重来」
   ```
3. 用户确认后，移除所有 `[AI推断]` 标记，写入落盘
4. 若用户修改了 AI 补全的某个字段，该字段视为"用户已填写"，不再标注
5. 落盘后触发「创建完成后的流转」（见下节），展示 A/B 选项

---

## 创建完成后的流转

> **适用范围**：补全确认流程 step 3（用户确认落盘后）或简化模式 step 3（用户确认落盘后）均触发此流转。

角色卡写入落盘后，AI 输出以下流转选项，**不自动推进到剧情或开局下一步**：

> 角色卡《{角色名}》创建完成。落盘到：
> A. 📁 通用角色卡目录 — 独立保存，任意小说/场景卡均可复用
> B. 📁 当前小说项目 — 仅当前小说内可用（若无活跃小说则不可选）
> C. 📁 通用 + 当前都存

- 若当前无活跃小说项目，B 和 C 灰显，仅 A 可选。
- 选 A / C → 自创角色自动归入 `{存储根}/通用角色卡/characters/自创/{角色名}/`，同步更新 `_roster.json`（`work: "自创"`）。若用户在创建时指定了作品名，则归入对应的 `characters/《作品名》/{角色名}/`。详见 `references/character-card-usage.md`。

```
✅ {角色名}角色卡已保存。

接下来：
A. [跳过] 不创建配角，结束角色创建，继续剧情/开局流程
B. [配角] 再创建一张配角角色卡
```

| 用户选择 | 行为 |
|----------|------|
| A — 跳过 | 退出深度创建模式。若处于开局流程中 → 生成卡即作为当前开局主角，回到开局流程的步骤 3（确认角色）；若在剧情中触发 → 恢复叙事，在下一段正文前追加一行 `💡 已创建角色：{角色名}`；**若由角色卡短篇触发（非开局流程、非剧情）→ 语义改为「返回选卡列表」，不推进到任何下一步** |
| B — 创建配角 | 回到创建流程第 1 轮（身份与外貌），新角色默认定位为「配角」。AI 在后续补全中会参考已创建的主角/配角信息确保人际关系与能力定位的一致性 |

**配角创建的特殊处理**：
- 配角创建同样使用九维模板，但 AI 补全时会根据已创建主角的身份、性格、阵营**自动推导**该配角与主角的关系
- 连续创建多个配角时，每次落盘后重复展示 A/B 流转选项，直到用户选择 A
- 配角之间的人际关系（维度⑧）同样在每次补全时交叉参考所有已创建角色

## 简化模式

若用户在一开始就只说了一个短语（如「一个冷艳的剑客」）：
1. AI 跳过四轮问答，直接基于描述生成九维完整卡片
2. 展示完整卡片 + 底部提示：
   ```
   > 以下为 AI 基于「{用户描述}」生成的初稿。
   > 确认输入「确认」| 逐项修改输入「改{字段} 新内容」| 重新来输入「重来」
   ```
3. 用户确认或逐项修改后落盘

## 与角色卡系统的衔接

- 自定义角色创建完成后，自动等价于该角色已"弹出角色卡"，后续 `弹出{角色名}角色卡` 正常展示
- 若该角色此前已有角色卡（蒸馏/叙事），自定义创建的新卡**覆盖**旧卡，AI 在覆盖前提示：「{角色名}已有角色卡，确认覆盖？」
- 落盘逻辑遵循 character_card.md §落盘逻辑 的角色类型判定规则
