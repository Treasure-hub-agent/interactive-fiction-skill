# 角色卡系统（P2 按需加载）

> 本章为互动小说创作中的角色管理工具。用户在剧情进行中可通过指令触发，以规范格式查看/修改角色设定。蒸馏角色修改后直接覆盖原文件；叙事角色修改后同步写入 `novel_runtime.json`。
>
> **与「关系」「人物志」的衔接**：AI 展示「关系」好感度一览或「人物志」角色名单后，必须在结果末尾追加引导行 `> 💡 输入「弹出{角色名}角色卡」查看该角色详细设定`。

---

### 触发指令

| 指令 | 行为 | 边界处理 |
|------|------|----------|
| `弹出角色卡` | AI 回复「请指定角色名，如：弹出{示例角色名}角色卡」 | — |
| `弹出{角色名}角色卡` | 直接弹出该角色的角色卡（默认九区块） | 角色名不存在 → 提示「未找到名为 {角色名} 的角色」 |
| `展开{角色名}的memory` | 在角色卡基础上追加完整背景故事时间线 | 若该角色尚未弹出过角色卡 → 先弹出角色卡，再追加展开层 |
| `修改{角色名}人设` | 先弹出当前角色卡，然后 AI 等待用户发回修改后的文本，对比变更并更新 | 若该角色近期已弹出过角色卡且上下文仍在 → 直接接受修改文本 |
| `改{角色名}的{字段}` | 直接定位字段并更新，无需复制整卡回传 | 字段名模糊匹配（性格≈性格区块、武器≈标志物品-武器） |

触发后 AI 不生成叙事正文，专注处理角色卡交互。

**存档恢复时角色卡归属判定**：用户通过 `加载存档 #N` 恢复进度后，AI 需检查该存档中角色卡所属的角色近期是否有过角色卡修改。AI 在加载存档恢复后自动输出一行归属提示。

### 角色卡格式

> **弹出 vs 存档格式差异**：弹出角色卡展示角色设定本体（九区块），不含好感度和最后场景——这两项属于动态游戏状态数据。

#### 默认弹出（九区块）

```
═══════════════════════════════
【角色卡】{角色名}
═══════════════════════════════

▎基本信息
  身份/定位：——
  存在形态：人类 / 非人 / 化身 / 组织 / 多身份——
  年龄：——
  籍贯/出身：——

▎外貌特征
  脸型：——
  眉眼：——
  发型发色：——
  身形：——
  特殊标记：——

▎标志物品
  武器：——
  载具：——
  其他：——

▎性格
  关键词：——
  内在矛盾：——

▎声线基因
  对话节奏：快/慢/欲言又止/机关枪——
  爱用句式：陈述/反问/省略/祈使——
  人称习惯：自称「」/ 他称偏好——
  情绪口头禅：激动时说「」/ 紧张时说「」/ 放松时说「」
  禁忌词：绝对不会说的词——
  非语言特征：手势/微表情/身体小动作——

▎关键背景
  ——

▎人际关系
  {角色名}：{关系性质} / {态度简述}

▎成长弧线
  起点状态：——
  转折点：第 章（事件）→ 变化：——
  终点状态：——
  可能黑化/反转：——

▎状态追踪
  当前位置：——
  当前目标：——
  携带物品：——
  当前情绪：——

═══════════════════════════════
> 展开指令：「展开{角色名}的memory」
> 修改：直接复制上方内容修改后发回，或使用「改{角色名}的{字段}」定位修改
> 深度创建：「自定义角色」进入AI引导式九维创建流程
> ⚠️ 建议先「存档」再修改 | 大幅修改人设可能导致前后文不连贯
═══════════════════════════════
```

标志物品区块为空时仍展示（字段+空值），鼓励用户补充。

> **底部提示行场景规则**：「建议先存档」提示行仅在爽文/主线模式的剧情阶段展示。场景卡模式中自动移除该行。

#### 展开 memory

```
═══════════════════════════════
【角色卡】{角色名} · 背景故事（展开）
═══════════════════════════════

▎关键事件时间线
  · {事件1} — {影响}
  · {事件2} — {影响}
  ...
═══════════════════════════════
```

#### 与蒸馏五维的映射

| 角色卡区块 | 对应蒸馏维度 |
|-----------|-------------|
| 基本信息 + 外貌 | profile |
| 标志物品 | 从 profile / memory 中提取 |
| 性格 | personality |
| 声线基因 | interaction（展开） |
| 关键背景（默认） | memory（摘要） |
| 人际关系 | relations |
| 成长弧线 | memory（时序化）+ personality（变化） |
| 状态追踪 | runtime（动态，不参与蒸馏） |
| 展开的 memory | memory（完整时间线） |

> 九维模板（deep_character_creation.md）→九区块映射：身份外貌→①②、角色定位→④⑤⑥、性格核心→④、内心动力→⑥、声线基因→⑤、关键背景→⑥、成长弧线→⑧、人际关系→⑦、能力技能→④

### 修改流程

1. 用户复制角色卡 → 修改内容 → 发回
2. AI 对比发回文本与弹出时的角色卡，智能识别变更区块
3. 仅更新有变化的区块，其余保持不变
4. AI 回复格式：「已更新{角色名}角色卡：{变更区块列表}」

**关系冲突检测**：修改涉及「性格」「声线基因」「关键背景」区块时，AI 需在更新后自动执行冲突检测。若发现冲突，生成冲突提醒行追加在 AI 确认行之后。AI 不得自动修改关系标注，仅提醒用户。

**D 选项同步**：角色卡修改后涉及「性格」「声线基因」「成长弧线」区块变更时，AI 在下一轮剧情生成的 D 选项必须同步采用修改后的特性。

**背景回溯冲突检测**：当用户口头设定或修改角色背景信息时，AI 需检测与已有背景的冲突。冲突时给出三项方案：A — 蒸馏角色方案 / B — 叙事优先方案 / C — 调和方案。无冲突时直接写入。

**修改后检查清单**（按序逐项执行）：

| 步骤 | 检查项 | 触发条件 | 操作 |
|---|---|---|---|
| 1 | 关系冲突检测 | 涉及性格/声线基因/关键背景时 | 检测冲突 → 仅提醒不自动修改 |
| 2 | D 选项同步 | 涉及性格/声线基因/成长弧线时 | 更新 D 选项推理基准 |
| 3 | 自检基准联动 | 涉及性格时 | 同步更新一致性自检基准 |
| 4 | 背景回溯冲突检测 | 涉及关键背景/成长弧线时 | 检测与已发生事件的矛盾 → 提供三方案 |
| 5 | 状态一致性校验 | 涉及状态追踪时 | 核对角色当前位置/携带物品与最近叙事是否一致 |
| 6 | 写入确认 | 以上全部通过 | 直接写入角色卡对应维度 |

### 落盘逻辑

| 角色类型 | 读取来源 | 写入目标 |
|----------|----------|----------|
| 蒸馏角色 | `{存储根}/{小说名}/characters/<slug>/` 或 `{存储根}/通用角色卡/characters/<作品名>/<slug>/` 下对应 `.md` 文件（取决于落盘上下文） | 直接覆盖对应维度的 `.md` 文件 |
| 叙事角色 | 从对话上下文提取 | 静态设定写入 `novel_runtime.json` 的 `cp{}`；动态状态（位置/目标/情绪/携带物品）写入 `novel_runtime.json` 的 `st{}` |
| 自定义角色 | 用户输入 + AI 补全 → 弹出确认后写入 | 蒸馏角色走蒸馏路径，叙事角色走叙事路径 |
| 静默生成角色 | AI 从对话历史中提取，不需用户确认 | 精简卡/完整卡均写入 `novel_runtime.json` 的 `npcs[slug]`，静默完成 |

蒸馏角色直接覆盖，不做备份。**若蒸馏角色此前经过本地修改**，在重新蒸馏前应提示用户确认。

**蒸馏角色名→slug 映射**：AI 通过蒸馏 Phase 4 已落盘的 skill 文件路径反向匹配。蒸馏 Phase 4 落盘时，目录 slug 生成为角色名的拼音全小写（空格替换为 `-`）。

**双向同步**：蒸馏角色的 skill 文件修改后，AI 需在下一轮剧情生成时加载新设定。

| 修改区块 | 同步影响 |
|----------|----------|
| 性格 | 下一次剧情中的角色言行、D 选项性格推断 |
| 声线基因 | 下一次剧情中的对话语气、节奏、措辞风格与非语言特征 |
| 关键背景 | 下一次触及该角色背景的剧情展开时的动机与立场基础 |
| 成长弧线 | 下一次剧情中的角色决策倾向 + 长期的弧线进度追踪 |
| 状态追踪 | 仅影响位置/物品一致性校验，不影响行为推断 |
| 基本信息 | 仅影响外貌/身份引用，不影响行为推断 |
| 标志物品 | 仅影响物品描写 |
| 人际关系 | 下一次与其他角色互动时带入新关系标注 |

### 静默生成角色卡格式

> 配角由系统静默自动生成角色卡时使用，不打断用户叙事流程。触发条件见 `extended/side_chars.md` §配角角色卡静默生成。

#### 精简卡（首次达标时生成）

```
【精简卡】{角色名}
  身份/定位：——
  外貌记忆点：——
  与主角关系：——
  性格关键词：——
  声线提示：——
```

5 字段，轻量。写入 `novel_runtime.json` → `npcs[slug]`。

#### 完整卡（再次达标时升级）

精简卡 + 以下六维扩展：
- 内心动力（动机+恐惧）
- 关键背景（出身+童年事件）
- 成长弧线（起点→可能方向）
- 能力技能
- 人际关系（与其他已创建配角的关系）
- 标志物品

完整卡，中等规模。覆盖写入 `novel_runtime.json` → `npcs[slug]`。

**升级时的 AI 操作**：
1. 从角色出场以来的所有对话和情节中提取信息
2. 按 `extended/deep_character_creation.md` 的补全推理链补全空字段
3. 写回 `npcs[slug]`
全程静默。

### 与现有系统的交互

| 场景 | 行为 |
|------|------|
| **爽文模式 / 主线模式** | 正常调用，角色卡指令优先于选项处理 |
| **场景卡** | 同样可用，但底部"建议先存档"提示不适用 |
| 沉浸模式 | 发出角色卡指令视为用户主动介入，自动退出沉浸 |
| **亲密场景进行中** | 暂停当前阶段推进，优先处理角色卡 |
| **蒸馏流程/角色创建/开局选择阶段** | 边界提示统一见触发指令「边界处理」列 |

### 交互约束

- 弹出角色卡后 AI 不自动生成叙事正文，等待用户下一步操作
- 角色卡展示为纯文本，不使用交互卡片
- memory 展开层的内容不写入角色卡主区块，仅追加展示
- AI 对比修改时仅比较结构化的区块内容，不比对格式线和提示语
