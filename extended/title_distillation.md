# 作品名检索蒸馏（路线 A 标题轻量入口）

> 本文件为 P2 按需加载。当用户在**路线 A（穿越成原著角色）**开局、未上传 txt 而直接给出作品名（或说"搜《XXX》"）时，按本流程联网检索并蒸馏世界观/角色/剧情。与"上传 txt 蒸馏"（distillation.md）产物完全一致，可后续补传 txt 做「深蒸馏」。

---

## 定位

- 本流程是「上传 txt 蒸馏」的**并列轻量入口**，覆盖绝大多数作品。
- 产物结构与 txt 路径一致：世界观速览 + 角色卡（五维）+ 主线大纲。
- 若用户同时上传 txt，优先走 txt 蒸馏（distillation.md），本流程不触发。

## 触发与确认（遵守蒸馏铁律）

- **触发**：路线 A 开局，用户输入纯作品名 / "搜《XXX》" / "《XXX》世界观"，且未附 txt。
- **联网检索前必须确认**（遵循 distillation.md §数据获取策略 铁律：禁止未经确认自行联网搜索）：
  - 若用户已明确指令"搜《XXX》" → 直接检索。
  - 否则 AI 先问：「未检测到 txt。是否**联网检索《XXX》**的世界观/人设/剧情来做蒸馏？（模型对该作已有一定了解，可直接生成；联网可获取更全/更准的资料）」→ 用户确认后检索。
- 热门二游/动漫模型知识通常较充分：AI 可先用模型知识出轻量底稿，再询问是否联网校正/补全。

## 固定检索套路（固定主干 + 题材加权）

### 固定骨架 L1 / L2 / L3

| 层 | 用途 | 源 | 固定 query 模板 |
|----|------|----|----------------|
| **L1 百科类** | 基础设定 / 人设 | 百度百科、维基百科（中·英）、萌娘百科（ACG） | `《{title}》世界观 设定` · `《{title}》角色介绍 人物设定` |
| **L2 专题站** | 深度世界观 / 势力 / 时间线 | Fandom、灰机wiki、作品专属 wiki | `{title} wiki 设定 势力 时间线` · `{title} fandom` |
| **L3 通用搜索** | 补遗漏 + 交叉验证 | 联网搜索 | `《{title}》剧情大纲 主线 结局` · `{title} 世界观解析 考据` |

### 题材加权前置（仅把最佳源提到 L1 最前，骨架不变）

| 题材 | L1 前置最佳源 |
|------|--------------|
| 网文 | 起点 / 晋江作品页 |
| 轻小说 / ACG | 萌娘百科 / Fandom |
| 传统出版 / 影视IP | 维基 / 豆瓣读书 |
| 游戏 | 萌娘 / Fandom(灰机) → 维基 / 百度 → 通用搜索(lore) |

**题材嗅探**：从作品名 + 首条搜索结果判断题材（网文看起点/晋江页、ACG 看萌娘、游戏看 Fandom/灰机/官网）。判定不确定时按「轻小说/ACG」默认（覆盖最广），不影响骨架。

### 游戏专属适配

- **搜索锁定 lore，避开攻略**：模板用 `《{title}》世界观 设定 考据` / `《{title}》剧情 角色 背景故事`，不要搜 `攻略 / 配装 / 数值`。
- **蒸馏支持分支/多结局**：主线大纲用「分支标注」（如 `主线A` / `分支B` / `真结局`），五维角色蒸馏不变。

## 收口纪律（达标即停）

- 每个核心维度（世界观 / 主角 / 主线）**≥2 源印证**即视为达标，收口。
- 固定最多打 **2–3 个源/维度**，不穷尽。
- 交叉验证发现矛盾 → 取多源一致项；矛盾项标注「存疑」。

## 蒸馏（复用现有 schema）

检索原料 → 走现有 **世界观蒸馏 / 角色五维蒸馏 / 剧情大纲蒸馏**（见 distillation.md）→ 产物与 txt 路径完全一致：

- 世界观速览（写入 `{存储根}/{小说名}/worldbuilding/世界观速览.md` 或对应结构）
- 角色卡（含五维，写入 `output/characters/<slug>/`）
- 主线大纲

### 搜索专属字段（写入 novel_runtime.json）

```json
{
  "distill": {
    "source": "title-search",
    "credibility": {
      "worldview": "多源印证 | 单源存疑 | 推算",
      "protagonist": "多源印证 | 单源存疑 | 推算",
      "mainPlot": "多源印证 | 单源存疑 | 推算"
    },
    "missing": ["未覆盖的维度1", "未覆盖的维度2"]
  }
}
```

## 兜底（缺失兜底，不编造）

- 关键维度不足（如主角仅 1 源、世界观完全查不到）→ 填 `missing` 清单。
- **主动提示用户**：「以下维度搜索资料不足：{missing}。可 ① 补传 txt 做深蒸馏 ② 直接补充设定」，不生成占位骨架。

## 与 txt 深蒸馏衔接

- 标题产物写入同一 `novel_runtime.json` / `output/` 结构。
- 用户后续补传 txt → 以搜索底稿为基础做「深蒸馏」：补全 `missing`、提升 `credibility`、用全文校正「存疑」项。
- 锚定机制（route_system.md §二）同样适用。

## 蒸馏完成后 · 落盘选择

蒸馏产物写入前，AI 询问：

> 角色卡《{角色名}》蒸馏完成。落盘到：
> A. 📁 通用角色卡目录 — 独立保存，任意小说/场景卡均可复用
> B. 📁 当前小说项目 — 仅当前小说内可用
> C. ↩ 先不落盘，以后再说

- 若当前无活跃小说项目，B 灰显标注"当前无活跃小说"。
- 选 A → 写入 `{存储根}/通用角色卡/characters/《作品名》/<slug>/`，自动按作品名创建子文件夹（详见 `references/character-card-usage.md`）。同步更新 `_roster.json` 的 `work` + `path` 字段。
- 选 B → 写入当前 `{存储根}/{小说名}/characters/<slug>/`。
- 通用角色卡目录与小说内目录的**文件结构完全一致**（SKILL.md + profile/personality/interaction/memory/relations.md + manifest.json）。

## 成本说明

- 检索蒸馏的输入规模远小于直接读取全文，成本可控。
