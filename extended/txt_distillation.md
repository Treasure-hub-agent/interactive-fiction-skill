# 原著 txt 读取与蒸馏（上传原文的规范通道）

> 本文件为 P2 按需加载。用户在开局或角色卡管理阶段提供原著 txt（文件或粘贴）时加载。与 `extended/title_distillation.md`（作品名检索）为**并列双入口**，下游产物同构：世界观速览 + 角色五维卡 + 主线大纲。

---

## 0. 定位与铁律

| 项 | 规则 |
|---|---|
| **触发** | 用户发来 txt 文件/路径、粘贴正文；或说「用这本原著开局」「深蒸馏」「补传原著」 |
| **与检索路径** | 有 txt 走本流程；无 txt 走 `title_distillation.md`；两者产物同构，可单向升级（检索底稿 → 补传 txt 深蒸馏） |
| **原文只读** | 原文落盘后不改写：不改编码、不切分原文、不重写文件 |
| **全文不进上下文** | 上下文只承载**窗口文本与中间产物**；禁止把全文整段灌入对话 |
| **脚本降级** | 脚本不可用时，用 read_file 分窗口读，本文件全部规则（预算、窗口、分批、落盘）逐条同构适用 |

## 1. 阶段一 · 接入落盘（0 轮等待）

### 1.1 落盘位置

| 场景 | 原文 | 索引 |
|---|---|---|
| 有活跃小说 | `{存储根}/{小说名}/source/<作品名>.txt` | 同目录 |
| 无活跃小说（独立蒸馏 / 角色卡管理） | `output/source/<作品名>/<作品名>.txt` | 同目录；建小说后随角色卡迁入 `{存储根}/{小说名}/source/` |

- 用户给的是路径 → 复制原文（原样，不改编码）；用户粘贴 → 原样写入 `source/<作品名>.txt`（作品名未知时用 `pasted.txt`）。

### 1.2 小文件快路径

全文 **≤ 5 万字** → 跳过索引，直接全文精读，流程从 §3.2 起（采样预算 100%）。

### 1.3 接入卡（输出后立即询问蒸馏深度）

```
📖 已接入原著《示例长篇》
   规模：1,240 章 · 218.6 万字 · 6 卷 · 编码 GBK（按 UTF-8 解析）
   角色候选：示例主角 4120 · 示例配角A 1880 · 示例配角B 1540 · 示例配角C 980
   索引：source/book_map.json · source/目录.txt
```

### 1.4 蒸馏深度（一次性询问，与「极速蒸馏」同一精神）

```
请选择蒸馏深度：
A. 标准蒸馏（推荐）— 世界观 6 维 + 主角 + 重要配角 3-5 张 + 主线大纲（采样 ≤ 全文 8%）
B. 精蒸馏 — 追加次要角色卡 + 分卷细纲（采样上限 12%，耗时更久）
C. 只取世界观/主线 — 不建角色卡（「自创角色」路线只借世界观）
D. 跳过蒸馏 — 直接凭模型知识开局
```

- 选 D → 原文与索引保留在 `source/`，用户随时可说「蒸馏这本原著」补跑
- 选 C → 只跑 §3.2 轮 1 与 §4.2 / §4.4（世界观与大纲），跳过角色卡

## 2. 阶段二 · 建索引（脚本 `scan`）

```
python3 scripts/txt_prep.py scan <原文路径> --out <source 目录>
```

产出两份派生数据（只读，删除后可重建）：

| 文件 | 字段 | 用途 |
|---|---|---|
| `book_map.json` | `file` / `encoding` / `bytes` / `chars` / `chapters[{no,title,start_line,end_line,chars}]` / `volumes[]` / `roles[{name,count,first_ch}]` / `lore_top[]` | 采样选区、回查定位、自检比对 |
| `目录.txt` | 逐行 `第N章 标题 · 本章字数` | 一眼掌握全书结构，省去逐章探查 |

### 确定性算法（四项 + 兜底）

1. **编码探测**：BOM → UTF-8 → GB18030 → UTF-16 逐级试解，全失败用 `replace` 兜底并标注；`slice` 输出统一 UTF-8
2. **章节切分**：`第N章/节/回`、`Chapter N`、`第N卷/部/篇`（中文数字与阿拉伯数字均支持）
3. **角色候选**：说话归属正则（`X说道/答道/问道/冷笑道…` + 引号接动词）→ 候选名 / 命中次数 / 首次出现章
4. **设定密度章榜**：统计设定标识词（境界/修为/功法/宗门/势力/大陆/组织/纪元/货币…）各章命中数取 Top → 世界观说明段优先采样
5. **无标记兜底**：整本无章节标记 → 按每 3,000 字切块，标 `块N`

### 索引读取纪律

`book_map.json` 在蒸馏期间常驻，**蒸馏结束后卸载**，只留 `目录.txt` 供回查——中间数据不滞留上下文。

## 3. 阶段三 · 分层采样蒸馏

### 3.1 预算表（判定锚点）

| 全文规模 | 采样预算 | 读取方式 |
|---|---|---|
| ≤ 5 万字 | 100%（全文精读） | 一次读完 |
| 5–50 万字 | 骨架 ≤3 万字 + 角色深采 ≤1.5 万字 | 分 8–12 个窗口 |
| > 50 万字 | 骨架 ≤4 万字 + 角色深采 ≤2 万字；总量 ≤ min(全文 8%, 6 万字) | 分 12–20 个窗口 |

**窗口** = 1 章或 ≤3,000 字，取小者；长章按 3,000 字切分。

### 3.2 轮 1 · 骨架采样（按优先级取满预算即停）

1. 开篇前 3 章（全取）
2. 每卷首章
3. 设定密度章榜 Top 10
4. 全书均匀抽样补齐剩余预算

**产出**：世界观速览（6 维）+ 主角档案 + 主线大纲（按卷）+ **角色名单分级**（主角 / 重要配角 / 次要）。

### 3.3 轮 2 · 角色深采

对名单内角色逐个 `slice --grep <角色名>` 取命中密度最高的 2–3 个窗口（每角色 ≤3,000 字）：

| 级别 | 产出 | 判定锚点 |
|---|---|---|
| 主角 | 完整五维卡 | 原文可支撑 ≥3 维 |
| 重要配角（3–5 名） | 完整五维卡 | 同上 |
| 次要角色 | 轻量卡：身份 / 性格关键词 3–5 / 关系定位 | 五维中 ≥3 维无法提取 → 轻量卡（复用 distillation.md §冷门配角轻量卡路径） |

### 3.4 分批纪律（防爆窗）

- 每批读 **4–6 个窗口** → 落一次中间产物 → 再读下一批；已读窗口内容随后不再保留在上下文，只留提炼结论
- 每批结束输出一行进度：`🔬 蒸馏中 3/8 批 · 已覆盖 42 章 · 世界观 6/6`
- **收口纪律**：世界观 3 维 + 主角 + 主线各得 ≥1 处原文支撑即可收口，不必读满预算

### 3.5 断点恢复

`_checkpoint.json` 增记 `source_file` / `phase` / `plan`（预算与采样章号）/ `read_windows`（已完成窗口）。中断后按 `distillation.md` §断点保存与恢复 的三选一继续（继续 / 重来 / 跳过）。

## 4. 阶段四 · 提取规范

### 4.1 证据级别

| 级别 | 定义 | 落盘要求 |
|---|---|---|
| `verbatim` | 原文原句 | 引用 + **章号**（`第12章`） |
| `artifact` | 同作多处一致的描述 | 至少 2 处章号 |
| `impression` | 其他角色评价 / 模型推断 | 标注推断来源 |

### 4.2 世界观 6 文件

写入 `worldbuilding/{overview,era,power_system,geography,society,narrative_tone}.md`。

**词条格式（硬要求）**：关键概念写成 `## 词条名` 或 `**词条名**`，长度 2–24 字——这是记忆外置助手（`scripts/novel.py` 的 `brief` 子命令）的 `[设定]` 检索唯一识别的格式，命中本轮关键词的条目才会进入每轮简报。

### 4.3 角色卡

复用 `distillation.md` 五维 schema（profile / personality / interaction / memory / relations + 证据标注），txt 路径增补：

- `interaction` 必须落 **3–5 句原句样本 + 章号**（声线、口癖、称呼习惯）
- `relations` 只写关系定位与影响，交叉事件在 `memory` 详写（与 distillation.md 同口径）
- 同作前后矛盾（设定漂移 / 战力崩坏 / 关系反复）写入 `conflicts.md`

### 4.4 主线大纲与时间线

- **主线大纲**：按卷/阶段输出；多结局作品用分支标注（`主线A` / `分支B` / `真结局`）
- **`source/timeline.md`**：逐章一行 `第N章 · 关键事件（≤40 字） · 出场角色`，长书按卷分区。仅供回查与锚定使用，**不参与每轮简报检索**（避免挤占 `[设定]` 的 ≤4 条预算）

### 4.5 不编造

低充足度维度标 `[待补]` 并在 Phase 5 汇报中列出；不凭空补全原文未提供的信息。

## 6. 回查通道（游戏中按需，不重读全文）

**触发**：场景切换 / 新章节开始 / 用户问「原著这段是什么」「查第 N 章」/ 每 10 个存档兜底一次。

**流程**：`slice --grep <当前进展关键词>`（或 `--ch N`）→ 读 1–2 个窗口（≤3,000 字）→ 对 `timeline.md` 比对 → **只输出结论**，不复述原文大段。

**偏差报告格式**：

```
🧭 原著比对 · 当前对应 第137章（本作已推进 11 章）
   一致：主角已入宗门、获本命法器
   偏差：原著中配角B此处尚未登场（本作提前 2 章）
   建议：下一段沿「宗门大比」推进
```

与「锚定钩子」（`seg_count % 8 == 0`）的关系：锚定钩子做设定自检，本回查做原著进度比对；同轮命中可并报，不重复复述。

## 7. 自检清单（txt 路径专属）

- [ ] `book_map.json` 章数与原文一致（章标记数 = 章节表长度）
- [ ] 所有引用章号存在于章节表内（禁止引用不存在的章）
- [ ] 抽检 3 条 `verbatim` 引用能用 `slice --grep` 在原文定位
- [ ] 世界观 6 文件非空，关键概念符合 `##` / `**加粗**` 词条格式
- [ ] 主角五维齐备；次要角色已按轻量卡降级或标注 `[待补]`
- [ ] `timeline.md` 覆盖全部卷
- [ ] `distill.missing` 已填写（无缺失则空数组）

---

## 8. 成本与收口

- 成本 ≈ 采样预算（大书典型 3–6 万字输入），远低于全文精读；索引为 KB 级
- **达标即停**：§3.4 收口纪律优先于「读满预算」
- 后续「深蒸馏」按需补窗口（补次要角色 / 补分卷细纲），不重跑全流程
