# v9.3.1 设计文档：自由输入优先 + 记忆核对

> 版本：9.3.1 ｜ 日期：2026-08-06 ｜ 状态：已批准（待实施）
> 定位：增量小版本（热修级），功能落地后下一版本再压 token。

---

## 一、背景与动机

实测反馈（双用户）与使用观察表明：

1. **自由输入是主要推进方式**：实际游玩中，用户更多直接输入行为/台词（「我掀桌走人」「『……你还记得我吗』」），而非机械选择 A/B/C/D/E。选项本质是**参考指引**，不应是叙事推进的唯一框架。
2. **长剧情一致性是最大痛点**（按痛点排序）：
   - B. 事件断链——前面发生的关键事件/说过的话，后面毫无回响
   - A. 设定错乱——角色名、关系、世界观细节记错、前后打架
   - C. 性格漂移——角色越玩越不像自己
   - D. 分支消失——选择后果未兑现
3. 互动小说是**长会话、长上下文、高推理**任务，token 效率是长期硬约束（本版先不设上限，下版瘦身）。

**核心定位**：以 skill 形式替代酒馆 AI（SillyTavern）的繁琐学习成本——记忆层由 skill 自动维护，用户零操作。

---

## 二、目标与非目标

### 目标
- 选项机制「参考指引」化，自由输入融入质量优先
- 长剧情一致性：引入记忆核对自检 + `choices[]` 后果回收纪律
- 为 v9.4.0 的 timeline / world_state 账本打地基

### 非目标（本版不做）
- 不新增外部记忆账本文件（timeline.json / world_state.json 留给 v9.4.0）
- 不新增 `open_loops` 运行时字段（复用升级现有 `choices[]`，保持 novel_runtime.json 结构兼容）
- 不做 token 硬上限与瘦身（下版本循环做）
- 不做生态/分发/跨平台扩展

## 三、详细设计

### 第一节：选项机制「参考指引」化

**现状问题**：铁律 #0 将「每轮跟五选项」设为最高优先级，选项成为叙事推进的唯一框架；实际使用中自由输入（行为/台词）是更常见的推进方式。

**改动**：

| 项 | v9.3.0 | v9.3.1 |
|----|--------|--------|
| 铁律 #0 定位 | 选项是剧情分支唯一推进器 | 选项是**参考指引 + 兜底**；用户自由输入是**等权/优先**的推进方式 |
| 自由输入融入 | 3 条归属规则（指令/选项/自由文本） | 升级为「自由输入即事件」：行为/台词直接成为当前帧事件，AI 展开叙事；不得旁白化/解释化/归错角色 |
| 选项生成 | 固定格式 + 策略标签硬约束 | 保留格式与标签（质量兜底），但选项**必须基于用户最近的自由输入状态展开**，与已发生的事自然衔接 |
| 台词处理 | 带引号内容由对应角色说出 | 强化：台词后本轮选项要**承接这句台词**的新局面（对话结句不再只是「危险陷阱」，而是「必须回应的当前帧」） |

**保留项（明确）**：
- **A/B/C/D/E 五选项 + 铁律 #0「每轮必跟」的形式完全保留**，只是语义从「分支框架」改为「参考指引」。
- **token 优化不新增机制**，沿用现有**「选项降级」规则**：场景仅支撑 3 个真分支 → 输出 A/B/C + D/E；仅支撑 2 个真分支 → 输出 A/B + D/E；**不硬凑 5 个选项**。降级后的 A/B 仍须满足互斥与独立约束。

### 第二节：记忆核对三查 + `choices[]` 后果回收纪律

#### ① 自检清单新增 3 项记忆核对

| 核对项 | 频率 | 规则 | 数据源（均现有，不引新文件） |
|--------|------|------|------|
| 设定核对 | 每轮 | 本轮正文是否与已知设定冲突（角色名/关系/生死/地点/能力） | `st{}`（位置/目标/情绪/携带物品）+ `cp{}` / `npcs[]` + 关系 + 上下文已知设定 |
| 后果核对 | 每轮 | `choices[]` 有 `surface_by` 到期条目？到期必须本轮或下轮回收 | `choices[]` 的 `surface_by` 字段 |
| 回响核对 | **事件触发** | 场景切换 / 时间跳跃 / 关键角色回归 / 新章节开始时执行：检查最近 3–5 个关键事件是否需要自然呼应；同一场景连续推进时**不强制** | `choices[]` 中 `type=consequence / foreshadow` 条目，`detail` 字段提供回响内容 |

> 回响核对由「每轮必查」调整为「事件触发」：同一剧情场景连续多轮时，每轮强制呼应既不现实也无必要。

#### ② 复用升级 `choices[]`，不新增 `open_loops`

**决策**：不新增 `open_loops` 字段/文件，直接升级现有 `choices[]`（v9.0.0 引入），保持 `novel_runtime.json` 结构兼容。

现有条目结构（确认）：
```json
{ "seg":12, "picked":"B", "tag":"稳健周旋", "type":"关系", "detail":"示例势力对主角仍存轻视", "tier":"即时", "surface_by":14, "foreclosed":["A","C"] }
```

**升级点**：
- `surface_by` = 回收节点（到期段落号；原设计草案中的 `due_seg` 直接复用此字段，不再新增）
- `foreclosed` = 未选路径/已关闭状态（未选选项的后果列于此，回收时同步核对）
- `type` 扩展枚举：`consequence`（选择后果）/ `foreshadow`（伏笔）/ `promise`（承诺），兼容现有取值（如「关系」等叙事类型值保留可用）
- 回收纪律：
  - 到期必回收，**正面呈现**（延续 v9.0.0「叙事显影」原则），禁旁白带过
  - 同时 open 条目上限 **5–8 条**，超出按「旧后果优先回收」
  - 拖延超 N 轮未回收 → 状态条轻提示

**服务目标**：B（事件断链——foreshadow 入列可回响）、D（分支消失——consequence 强制回收），并为 v9.4.0 的 timeline/world_state 账本打地基。

## 四、风险与取舍

- **token**：本版每轮预估增量 150–400 tokens（自检 + 队列核对）；选项 token 优化靠既有「选项降级」规则，不新增机制；不做硬上限，下版本瘦身循环处理
- **自由输入优先的边界**：自由输入成为主线后，需防「选项退化为装饰」——保留每轮必跟选项作为兜底与参考
- **`choices[]` 队列膨胀**：以 5–8 条上限 + 到期强制回收控制
- **兼容性**：不新增运行时字段，novel_runtime.json 结构不变，旧存档无缝兼容
