# v9.3.1 设计文档：自由输入优先 + 记忆核对

> 版本：9.3.1 ｜ 日期：2026-08-06 ｜ 状态：已批准（待实施）
> 定位：增量小版本（热修级），功能落地后下一版本再压 token。

---

## 一、背景与动机

实测反馈（双用户）与使用观察表明：

1. **自由输入是主要推进方式**：实际游玩中，用户更多直接输入行为/台词（「我掀桌走人」「『……你还记得我吗』」），而非机械选择 A/B/C/D/E。选项本质是**参考指引**，不应是叙事推进的唯一框架。
2. **长剧情一致性是最大痛点**（按痛点排序）：
   - B. 事件断链——前面发生的关键事件/说过的话，后面毫无回响
   - A. 设定错乱——角色名、关系、世界观细节记错、前后打架
   - C. 性格漂移——角色越玩越不像自己
   - D. 分支消失——选择后果未兑现
3. 互动小说是**长会话、长上下文、高推理**任务，token 效率是长期硬约束（本版先不设上限，下版瘦身）。

**核心定位**：以 skill 形式替代酒馆 AI（SillyTavern）的繁琐学习成本——记忆层由 skill 自动维护，用户零操作。

---

## 二、目标与非目标

### 目标
- 选项机制「参考指引」化，自由输入融入质量优先
- 长剧情一致性：引入记忆核对自检 + 后果回收队列
- 为 v9.4.0 的 timeline / world_state 账本打地基

### 非目标（本版不做）
- 不新增外部记忆账本文件（timeline.json / world_state.json 留给 v9.4.0）
- 不做 token 硬上限与瘦身（下版本循环做）
- 不做生态/分发/跨平台扩展

## 三、详细设计

### 第一节：选项机制「参考指引」化

**现状问题**：铁律 #0 将「每轮跟五选项」设为最高优先级，选项成为叙事推进的唯一框架；实际使用中自由输入（行为/台词）是更常见的推进方式。

**改动**：

| 项 | v9.3.0 | v9.3.1 |
|----|--------|--------|
| 铁律 #0 定位 | 选项是剧情分支唯一推进器 | 选项是**参考指引 + 兜底**；用户自由输入是**等权/优先**的推进方式 |
| 自由输入融入 | 3 条归属规则（指令/选项/自由文本） | 升级为「自由输入即事件」：行为/台词直接成为当前帧事件，AI 展开叙事；不得旁白化/解释化/归错角色 |
| 选项生成 | 固定格式 + 策略标签硬约束 | 保留格式与标签（质量兜底），但选项**必须基于用户最近的自由输入状态展开**，与已发生的事自然衔接 |
| 台词处理 | 带引号内容由对应角色说出 | 强化：台词后本轮选项要**承接这句台词**的新局面（对话结句不再只是「危险陷阱」，而是「必须回应的当前帧」） |

**保留项**：选项仍然**每轮必跟**（保留铁律 #0 形式），只是语义从「分支框架」改为「参考指引」——互动小说的标志体验不变。

### 第二节：记忆核对三查 + 后果回收队列

#### ① 自检清单新增 3 项记忆核对

| 核对项 | 频率 | 规则 |
|--------|------|------|
| 设定核对 | 每轮 | 本轮正文是否与已知设定冲突（角色名/关系/生死/地点/能力） |
| 后果核对 | 每轮 | open_loops 有条目到回收点？到期必须本轮或下轮回收 |
| 回响核对 | **事件触发** | 场景切换 / 时间跳跃 / 关键角色回归 / 新章节开始时执行：核对最近 3–5 个关键事件是否需要自然呼应；同一场景连续推进时**不强制** |

> 回响核对由「每轮必查」调整为「事件触发」：同一剧情场景连续多轮时，每轮强制呼应既不现实也无必要。

#### ② `choices[]` 升级为 `open_loops` 后果回收队列

落盘于 `novel_runtime.json`，替换/升级现有 `choices[]` 账本（v9.0.0 引入）。

**条目结构**：
```json
{
  "id": "loop_012",
  "content": "向林昭承诺明日归还玉佩",
  "type": "promise | consequence | foreshadow",
  "created_seg": 34,
  "due_seg": 40,
  "status": "open | seeded | closed"
}
```

**回收纪律**：
- 到期必回收，**正面呈现**（延续 v9.0.0「叙事显影」原则），禁旁白带过
- 同时 open 上限 **5–8 条**，超出按「旧后果优先回收」
- 拖延超 N 轮未回收 → 状态条轻提示

**服务目标**：B（事件断链——关键事件入列可回响）、D（分支消失——选择后果强制回收），并为 v9.4.0 的 timeline/world_state 账本打地基。

## 四、风险与取舍

- **token**：本版每轮预估增量 150–400 tokens（自检 + 队列核对），不做硬上限；下版本瘦身循环处理
- **自由输入优先的边界**：自由输入成为主线后，需防「选项退化为装饰」——保留每轮必跟选项作为兜底与参考
- **open_loops 队列膨胀**：以 5–8 条上限 + 到期强制回收控制

## 五、后续计划（v9.4.0 方向）

- `timeline.json`（事件时间线）治理 B 事件断链
- `world_state.json`（世界状态）治理 A 设定错乱
- 角色状态锚点治理 C 性格漂移
- 严格切片注入，预算上限每轮 ≤1,200 tokens
